# P5.3.2 冻结批次 PPO 对照

```powershell
python tools/RL/check_ppo.py
python tools/RL/short_ppo.py work/p532
.\scripts\train-rl.ps1 -Output work/ppo-smoke -Games 20 -TrainingOptions @('--trainer','ppo','--rounds','1')
.\scripts\train-rl.ps1 -Output work/p532/closed -Games 200 -TrainingOptions @('--trainer','ppo','--rounds','3','--reuse-first','work/rl-p53/round-01')
```

Legacy 仍为训练入口默认。原训练器按随机决策顺序切为 128 条的计算块，以每局逆长度加权，一轮仅清零一次、累积梯度、裁剪并调用一次 AdamW step，Actor 与 Critic 一起更新。三轮分别有 14,239/16,719、10,524/12,310、10,649/12,468 条有效 Actor/总决策，强制动作约 14.5–14.8%。同局共享胜负，样本相关；P5.3.1 实测按对阵梯度合向量范数仅为各对阵范数之和的 18–22%。

PPO 按游戏随机交错取样，每 epoch 使用所有样本一次，尾批保留。默认同一游戏各决策权重之和为 1，支持 --weighting decision。默认 Actor/Critic 各 256、各一 epoch、学习率 .0002、clip .2、熵 .01、最大平均 KL .01，参数通过 TrainingOptions 修改。无显式对阵重加权。Monte Carlo 回报从当前行动席位计算；Actor 优势使用冻结 Critic，未标准化。只接收冻结模型哈希匹配的 Policy-only 决策。强制决策仅训练 Critic。保留原温度、完整候选和实采动作 logprob，用它计算重要性比率。每步计算整个冻结 Actor 批次的 KL、近似 KL、分位数、熵、裁剪比率、梯度与权重变化。KL 超限或熵下降超过 25% 会撤销该步权重和优化器状态；数值异常使本轮失败。原 schema 1 不变。

## 20 局和 200 局

20 局冒烟执行 6 次 Actor、7 次 Critic 更新，平均 KL .000109。200 局固定轨迹对照直接复用了 Legacy 首轮的两份校验过的行为分片，双方初始化和评测种子相同。Legacy 一次更新；PPO 56/66 次，实际平均 KL .000684，对照旧 .00000731；平均 TV .01244，对照旧 .00129（全批、游戏加权口径略有不同）。首轮最大 KL .01054、P95 .00244，最终 clip fraction .0366%。冻结模型概率重算误差三轮最大约 2.06e-7。

## 短线

规则树、初始化、种子及采样预算相同，3 个种子，每个 6 批共 1,200 条短轨迹。每轮更新后两组各自采样。PPO 使用 32 决策 minibatch；Legacy 每 200 条轨迹一次更新。留出精确期望胜率如下。
