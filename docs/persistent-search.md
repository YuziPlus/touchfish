# P3.2 持久化搜索会话

## 接口和生命周期

- 新增 src/PersistentSearchSession.cs、src/SearchTreeReuse.cs、tests/SearchTreeReuseChecks.cs。
- 修改 src/ExtremeSearch.cs、src/FastSimulation.cs、src/MatchEngine.cs、src/SpellAnimationRules.cs、tests/DynamicDecisionFixture.cs、tests/ExtremeSearchBenchmarks.cs、tests/RuleTests.cs、tests/core-sources.json、scripts/test.ps1。
- 每场对局创建一个 PersistentSearchSession。Choose 返回对应当前合法动作的票据。Execute 验证对局身份、状态版本、当前观察、动作结构和实际实例 ID，调用正式规则。失败、过期或重复票据不推进。成功动作后按观察查找旧边的后继并立即解除对旧根及兄弟分支的引用。下次 Choose 重建 P2 后再次确认，任何不兼容情形冷启动。
- 通过弱键绑定真实对局，树和会话不保存 MatchEngine、权威快照、已采样世界或真实对手私有状态。公开历史保留观察者允许的事件版本和前缀，另保留观察键、席位、成功动作版本、P2 模型版本、搜索配置及上次已执行动作。

## 兼容性与有效访问

对比 P0 观察、己方手牌属性、公开英雄与随从附加状态、合法动作集合和己方动态候选。跨实际动作还须验证 P2 当前支持该历史、双方授权固定构筑均能得到唯一台账、两边隐藏分配的条件保持等价、历史只追加该动作支持的事件。未知构筑、多来源台账、奥秘、强制牌库约束、未认证触发、抽牌和跨回合均保守冷启动。普通无附加效果的随从出牌、确定性攻击和少数确定性英雄技能有受验证的路径。

真实结果必须命中该动作在树里的实际观察后继。随机法术当前未做安全复用认证。动态决策可以在已生成的私有候选和已知效果兼容时复用，例如仅获得己方已选卡、且下一次决策已在树中出现。选项以稳定 ID 比较，执行仍使用当前实际决策 ID。随机候选由规则引擎生成，搜索不会修改真实 RNG。

旧根的动作或回合截断点比新根近。跨动作时，仅在对应子树所有已记录访问均到达真实终局时，才继承访问次数、可用次数和价值。包含截断估值的子树整体弃用，避免从混合样本中只挑出终局样本。同一版本、信息与配置下重复调用，可以继续累计原根统计。续跑按状态版本、继承访问和续跑序号派生搜索种子，避免重复使用同一采样序列。取消前未开始的调用保留原会话；中途有未完整评估迭代或出现执行拒绝时，不保留受影响的树供下次复用。

FixedNewIterations 总是申请同样数量的新迭代。TargetEffectiveVisits 只用经验证的继承访问抵扣新迭代。结果分别给出继承访问、新迭代和实际有效访问。时间节省在对照实验中实测。

保留原 P3 的 UCT、固定启发式对手、rollout、估值和深度。会话受原 MaxNodes 与独立估算内存上限约束，默认树估算上限 32 MiB。重定根不保留旧分支，达到内存上限时停止扩展，根合法动作都放不下时给出合法回退。该预算是树结构估算，实际进程内存见对战记录。

## 验证

34 项 P3.2 专项、30,153 项相关规则检查通过。覆盖真实动作校验、实例映射、出牌、攻击、英雄技能、动态候选匹配、随机结果冷启动、隐藏信息置换、P2 不支持、时间视野失效、取消及内存上限。正式客户端编译和 WPF 外观预览通过。保留旧三个 AI 和正式界面入口。

两步斩杀专项基准，20 个配对种子，统计第二步选招。三种方式均完成 20/20 次斩杀。

| 模式 | 平均继承 | 平均新迭代 | 平均选招耗时 |
| --- | ---: | ---: | ---: |
| 冷启动 | 0 | 160 | 8.01 ms |
| 固定新增 | 155 | 160 | 8.12 ms |
| 目标有效访问 | 155 | 5 | 0.60 ms |

## 动物园镜像

每组 100 局，使用相同 952001–952100 种子和先后手。保持通用 32 世界换牌、对手旧动物园策略、已知构筑先验和此前 100 迭代对照配置。三个模式均为 52 胜、48 负。逐种子核对了结果、结束回合、决策数和模拟动作/迭代数一致。两种会话模式均为 0/2,298 次实际搜索复用。

固定新增和目标有效访问的平均每局累计搜索用时分别为 4,758 和 4,881 ms，冷启动为 4,585 ms。同机多进程运行的墙钟存在调度噪声，精确计数确认没有节省任何新迭代。失效主要是尚未认证的战场效果，占全部决策 63.6%，其次是外部实际操作造成的版本变化，占 21.2%。完整的 P95、每秒迭代、节点、峰值内存、GC 和失效分布见 work/zoo-p32-reuse/report.md。

正式对战没有观察到节省时间或胜率提升，因此维持冷启动默认。局部战术收益说明机制能在证据满足时工作。下一轮优先扩大可验证的公共效果范围，或验证视野对齐的统计；在实战覆盖率得到证实前，不宜引入后台持续思考。自适应预算可以先作为独立实验，根据经验证的有效访问量调节。

## 复现

先运行 scripts/test.ps1 -Scope search-tree-reuse。设置 TOUCHFISH_REUSE_TACTICAL_BENCH=1 可同时跑斩杀对照。镜像对照使用纯规则测试程序的 zoo-budget-match 入口，设置 TOUCHFISH_ZOO_REUSE 为 cold、fixed 或 target，TOUCHFISH_SEARCH_MATCH_BUDGETS=100，TOUCHFISH_SEARCH_SEED_START=952001，TOUCHFISH_SEARCH_GAMES=100。工作目录中的 run.py 提供八进程分片和汇总。
