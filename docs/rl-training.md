# P5.3 自我对弈 Actor–Critic

```powershell
.\scripts\train-rl.ps1 -Output work/rl-p53 -Games 200
python tools/RL/diagnostics.py work/rl-p53
```

命令默认迭代三轮。需要本地 P5.1、P5.2 权重和原数据集、OOD 配置。通过 TrainingOptions 传入 --start、--critic、--historical（可重复）、--self-fraction、--fixed-training、--temperature、--lr、--rounds。--random-init 使用固定种子随机 Actor。--rollback 路径校验模型格式并回写 champion 指针；从指定权重另起训练使用 --start 与 --critic。相同目录续跑复用经哈希校验的已完成批次，按轮确定性重做单步更新；本版不恢复轮内优化器进度。

Rollout 使用正式 MatchEngine，支持 uct、policy、puct 和现有专用 AI 对手。两席独立 RNG 和模型，Policy-only 对合法候选做温度 softmax 后采样，包括双方确认前的换牌和动态选择。概率按实际离散 RNG 区间质量记录。JSON schema 1 每个完成局一个文件，含公开与己方合法观察编码 x、动作编码 features、实际候选索引 pick、行为概率 probs/logprob、温度、双方模型哈希、行为类型、资格标志及最终赢家。训练收益由赢家与席位严格导出，胜/负/和为 1/0/0.5。搜索和专用 AI 的行为概率为 null，强制动作记录 1。异常局只写错误诊断。

PyTorch 重算 C# 行为概率并验证，Actor 仅学习本轮冻结采样版本的非强制 Policy-only 动作。Critic 也利用该版本的强制局面。每轮在冻结参数上累积一次 game-weighted Monte Carlo actor–critic 梯度，然后全局裁剪并更新一次。优势为终局结果减去脱离梯度的 Critic 概率，Actor 加 0.01 熵奖励。无需 PPO 概率比率，也不重复用旧轨迹更新。候选权重按 P5.1/P5.2 格式原生加载。Champion 保留，除非冻结对手配对正向显著、各筛查不掉胜场且独立种子确认通过。实验候选链独立于 champion 晋升状态。

## 实验

先跑 20 局工程批次，之后正式三轮各采 200 局。正式使用动物园、冰法、奇迹贼、心火牧、动物园换牌变体和铺场法师；独立 OOD 是铺场贼镜像。每轮约一半同版本自我对弈，一半对冻结 P5.2。每项评测用相同对局种子、构筑和先后手对照更新前后，轮间换种子。PUCT 与 UCT 对手同为 16 次预算；Policy-only 与其他模式不做等时效率结论。

| 轮次 | Actor 样本 | 冻结旧策略 /20 | 内置冰法 /8 | OOD /8 | PUCT 对 UCT /8 |
|---|---:|---:|---:|---:|---:|
| 1 | 14,239 | 9→9 | 0→0 | 4→4 | 7→8 |
| 2 | 10,524 | 15→16 | 0→0 | 5→5 | 4→4 |
| 3 | 10,649 | 14→14 | 0→0 | 6→6 | 5→5 |

行为概率最大误差约 2.03e-7，Actor 与 Critic 哈希均变化，固定 64 个观察的平均策略 TV 每轮约 0.0010–0.0011。首选变化分别 1、0、1 个。冻结对手改善最强的一轮仅净胜一场，单侧精确配对 p=.5。三轮均未晋升。未发现明显动作坍缩；同策略自对弈平均约 22–23 个引擎回合，但更新幅度和评测都小。OOD Critic Brier 前两轮上升，第三轮下降。固定冰法始终没有胜场，PUCT 仅第一轮净增一场，尚无迁移或增大规模的正向证据。

每轮梯度计算约 0.32–0.49 秒，不含采样、验证及 I/O。正式目录 JSON 约 165 MB。对局推理及决策耗时、先后手和回退数在 evaluation.json；逐种子在各 paired.json；概率例子在 training.json；对局构筑、职业、胜负及用时原始记录在各批次。正式客户端编译、WPF 外观预览、19,476 条规则检查和 P5.2 原生推理检查通过。另复跑两局，剔除计时后概率、动作和终局逐条一致。

当前验证为串行工作流，未测试并行采集或多进程写同一输出目录。OOD 实战只覆盖一个组合，固定基准本轮只用了冰法。默认正式搜索仍为 UCT + Heuristic。
