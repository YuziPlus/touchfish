## 更新与回退

首次从 https://github.com/YuziPlus/touchfish/releases 下载对应版本完整包，解压整个目录。之后在“更新日志 → 版本更新”点击“检查更新”，选择版本并下载；校验通过后点击“安装重启”。选择较早版本即可回退，历史程序包只保存在 GitHub。

检查版本优先读取 GitHub Releases 的 Atom 订阅，不依赖匿名 REST API 配额；订阅不可用时再使用 API。403 可能来自 API 限流或网络/代理限制，程序会显示各通道的完整错误。旧版若无法检查更新，请手动下载新版一次；此改动无法解除网络对所有 GitHub 域名的封锁。

更新仅替换程序和内置牌库，卡组、草稿、preferences.ini 保留。安装期间临时保留恢复数据，成功或恢复完成后清理；本地不长期保存历史版本备份。对局中允许检查与下载，需结束对局或离开房间后再安装。安装失败自动恢复原版本；新版有启动检查。

回退到 v0.1 / v0.1.1 后，旧主程序没有更新入口，但保留独立 `Touchfish.Update.exe`；关闭游戏后双击它，可从 GitHub 下载版本重新升级。双方联机需使用同一份版本包。

源码仓库：https://github.com/YuziPlus/touchfish 。发布包与源代码分开，Releases 包不含个人卡组和设置。

解压完整包，双击 Touchfish.exe。data 文件夹必须与程序同目录。Windows WPF 桌面程序，无需浏览器、Python 或现代 .NET SDK 来运行；需要 .NET Framework WPF 环境。

## 开始对战

启动进入局域网对战页。双方使用同一份完整程序包，连接同一局域网，各自选择自己的职业和卡组。

1. 一人点击“创建房间”，地址字段自动显示完整 `IP:端口`，点旁边“复制”即可分享，也可选中文字按 Ctrl+C。多网卡时点地址末尾小下拉切换地址。默认 TCP 端口 42671，可以修改。
2. 另一人填写房主地址，点击“加入”。地址可写成 `192.168.1.8:42671`；不带端口时使用端口输入框的值。
3. 连接并验证程序、牌库与卡组后，双方分别选择起手换牌，全部确认后开局，后手额外获得幸运币。房主先手，双方始终从自己的视角操作，结束回合直接交给另一台电脑。
4. 对局里点“房间”可返回连接页，再点“返回对局”继续。点“离开”关闭连接，重开一局需要重新建房和加入。

若 Windows 显示防火墙提示，允许在专用网络中访问。连接失败时检查地址、端口、双方是否在同一网络，以及路由器是否启用了设备隔离。仅支持局域网 IPv4 直连，不提供公网匹配、自动对手或断线续局；断线后双方停止操作并重新建房。

本地自对战仅从顶栏小 `test` 按钮进入，用于测试时选择双方职业和卡组。双方开局均为 10 个满水晶；对局标题栏的小“取”按钮可从己方剩余牌库选择一张移入手牌，保留十张手牌上限，取牌不耗法力；满手牌时先使用手牌。同机测试结束回合会交接手牌；正常“对战”入口只打开局域网功能。已连接房间时，需要先离开再进入 test。

- 想直接试操作，可选择“基础练习卡组”，九职业都提供合法 30 张卡组。
- 可选择当前编辑卡组或已经按代码保存的卡组，职业必须匹配。若含未实现效果，会明确列出并阻止开局。
- 攻击：点己方随从，再点敌方随从或敌方英雄。
- 随从：点手牌，再点己方空槽召唤；定向战吼需要选目标，无合法目标的战吼允许正常召唤并失效。
- 精确放置：右上角小“位”开关默认关闭。开启后选随从牌，已有己方随从下方临时出现“左 / 右”，点击即可插入相邻位置；例如 ABC 中点击 B 的“左”，D 会排成 ADBC。有定向战吼时先选位置，再选目标。空场仍点空槽；放置完成或取消后隐藏左右按钮，再点“位”可关闭此功能。
- 定向法术：点手牌，再点合法目标；没有目标的法术和武器在点牌时直接使用。
- 英雄技能：点“技”。法师与牧师再点目标；进入暗影形态后的其他职业同样选目标。
- 英雄对话：右键己方英雄，在底部两列菜单选择固定语句；双方共享气泡，停留两秒后淡出；极简模式禁用对话入口和发送。
- 英雄攻击：点装备后的“武”，或点顶栏“攻”，再点敌方目标。
- 点卡牌上的微小省略点查看详情，不会使用卡牌或发起攻击；“取消”清除操作选择。
- 手牌详情显示费用、随从的攻击/生命或武器的攻击/耐久，并显示完整效果；内容较长时滚动查看。
- 上边栏“记录”展示双方共享的公开对局历史：出牌与目标、攻击伤害、抽牌数量、疲劳、阵亡和回合切换。未公开的手牌名称不会出现在抽牌记录中。离开房间后仍可查看上局记录；记录保存在内存，退出程序后不恢复。
- 手牌超出宽度时使用滚轮横向查看，最多十张；查看详情和选择目标不改变手牌内容。
- 点“结束”交出回合；局域网自动同步，本地 test 则显示交接页遮住手牌，下一位玩家点“继续”。
- 本地 test 的“新局”回到测试职业选择；“返回对局”恢复当前对局。对战状态保存在内存，退出程序后不恢复。

联机由房主统一校验和结算，客户端发送操作请求；换牌期间双方分别确认；对话双方均可发送，出牌、攻击、技能和结束回合仅当前玩家能操作。客户端只收到自己的手牌、双方公开战场与资源、剩余牌数，不会收到对手手牌或任何牌库顺序。操作包含对局标识与状态版本，重复或过期操作会被拒绝。房主程序负责完整对局状态。

当前支持 382 / 382 张经典卡进入对战。支持范围见 previews/match-rule-coverage.json。已接入基础攻击、同时伤害、嘲讽、圣盾、风怒、冲锋、剧毒、潜行、冻结、扰魔、部分战吼与亡语、攻击光环、法强、武器耐久、九职业英雄技能、法力和过载、抽牌/爆牌/疲劳及胜负判定。

这不是完整经典规则实现。奥秘、多数持续触发与复杂复制等效果尚未接入；回合倒计时与断线续局也未接入。不能把已接入卡牌数量当作所有交互均与原版逐一核验。

## 组牌流程

筛选栏可选择“本职+中立”“职业卡”或“中立卡”，与费用、类型和搜索组合；默认筛选下搜索仍能找到其他职业牌，但不能加入卡组。

1. 顶部选择职业和卡池，编辑卡组名称。
   尚未实现对战效果的卡在牌库、卡组列表和详情中标注“【暂不可用】”；仍可浏览和组牌，但含这类卡的卡组暂不能开局。标记按规则实现状态自动更新。
2. 输入名称、效果或卡牌 ID 搜索，按费用与类型筛选。“全库”浏览全部卡牌；其他职业的牌可以看详情但不能加入当前卡组。
3. 点击名称看效果，点 + 加一张，卡组侧点 − 移除。双击牌库中的行也可加入；支持撤销、新建。
4. 必须恰好 30 张；同一普通卡最多 2 张，同一传说卡最多 1 张。完成后“导出代码”一键复制代码。
5. 点击“导入代码”，手动粘贴后点导入，或点“粘贴并导入”。兼容单行代码及带 # 注释的常见卡组文本。失败时当前卡组保持原样。
6. “保存”将完整卡组按代码存入本地列表；“打开”恢复已保存卡组。未完成草稿自动保存并在下次启动恢复。

核心是一串 Deckstring v1 代码。九职业代码已用 HearthSim 独立实现解码并逐字节重新编码核对；没有进行炉石客户端实际互操作测试。

设置页选择 WPS / Codex（浅色、深色）、普通 / 极简，即时生效并保存在 preferences.ini。
Codex 深色主背景为 `#0D1117`，文字前景为 `#E6EDF3`。

- 普通：548 × 474。
- 极简：392 × 300。
- 所有字体为正常字重，无卡图，办公工具面板外观固定。
- 组牌页显示名称方便选牌。对战页的极简模式隐藏名称，只显示攻、效果、血及小详情入口，武器为“武”、技能为“技”；同时出现较多效果时用单字缩写避免溢出。
- 尺寸为 Windows 逻辑像素，系统缩放影响实际显示大小；窗口可手动放大。

历史静态样例仅用于回归渲染；用户入口“对战”连接局域网对局，顶栏 test 为本地自对战。组牌、代码与外观设置继续可用。

## 开发与验证

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
.\Touchfish.exe --preview previews
powershell -ExecutionPolicy Bypass -File scripts/fetch_reference.ps1
python scripts/verify_reference.py
```

build.ps1 使用系统 .NET Framework 编译器。Python 只用于数据导入和独立核对脚本。

预览从真实 WPF 控件树生成图像，并检查牌库、代码、组牌、扩展、对战模型与输入处理器。对战测试覆盖非法操作不扣资源、关键词、武器、英雄技能、七槽限制、疲劳、死亡替换位置、选来源再选目标，以及九职业练习卡组打完整局的自动验证。联机测试使用真实 TCP 回环连接与两个 WPF 界面，覆盖连接、固定视角、手牌隐私、攻击/法术/技能/武器/位置/战吼同步、过期请求拒绝、版本不符、断线停用。结果见 previews/verification.txt、match-verification.json、match-simulations.json、lan-verification.json。验证不修改用户的设置、草稿或剪贴板；自动网络验证限于本机回环；用户与朋友已进行局域网试运行并反馈可运行。自动验证不是实机鼠标验证，也不代表与炉石客户端逐帧对照。

- src/CardLibrary.cs：牌库来源接口、数据索引、组牌限制与代码编码。
- src/DeckBuilder.cs：组牌、卡组列表、代码导入导出 UI。
- src/Panel.cs：窗口、主题、极简预览与设置。
- src/LibraryVerification.cs：验证与隔离扩展测试。
- src/MatchEngine.cs：对局、单位、资源、回合、攻击与结算状态。
- src/MatchRules.cs：显式卡牌效果与基础练习卡组。
- src/MatchUi.cs：职业/卡组选择、先选来源再选目标的单击操作与回合交接。
- src/MatchVerification.cs：战斗语义、点击处理器、布局与整局自动验证。
- src/LanProtocol.cs：TCP 消息、版本校验、房主结算与隐去手牌的状态快照。
- src/LanUi.cs：创建/加入/离开房间、网络操作请求与双方固定视角。
- src/LanVerification.cs：两个 WPF 界面通过真实 TCP 通信的集成验证。
- src/MatchRecords.cs：共享对局记录页面与手牌详情数值。
- src/MatchVisualEvents.cs、src/MatchVisualEffects.cs：结构化视觉事件、去重游标、效果渲染接口与普通模式动画。
- src/VisualVerification.cs：效果阈值、网络同步、死亡目标和极简模式验证。
- src/ReleaseNotes.cs、src/AssemblyInfo.cs：版本标识与应用内更新日志；完整记录见 CHANGELOG.md。
- src/UpdateCore.cs、src/UpdateUi.cs：GitHub 更新、校验、安装事务与历史版本选择。
- updater/Program.cs：独立安装/恢复程序；旧版回退后可双击管理版本。
- scripts/make_release.py、scripts/publish.ps1：生成运行包和更新清单，验证后发布 GitHub Release；`.github/workflows/release.yml` 可在 Actions 中手动运行。
